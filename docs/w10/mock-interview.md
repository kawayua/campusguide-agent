# W10 模拟面试脚本（30–40 分钟）

> 目标：能在 30 秒内说清项目；对 8 个高频追问给出有数字、有取舍、有失败的回答；不被追问击穿。

## 0. 开场（2 分钟）

面试官：用 30 秒介绍一下你最近的项目。

候选人：用 `30s-intro.md` 中文版；控制在 4 句话内，最后一句主动带 W7 失败。

## 1. 项目动机与范围（5 分钟）

1. 为什么选高校制度文档？  
   - 公开、可核验、有版本/受众/流程，适合练“引用可追溯”的 RAG。
2. 为什么只做华南农业大学？  
   - 单校可控；跨校会引入不同制度口径，首版不做。
3. 为什么不做通用聊天？  
   - 目标是条款级问答 + 办事 checklist，不是开放域助手。

## 2. 技术深挖（10 分钟）

1. 条款怎么切？  
   - 第 X 条/章；section 单独；part 共享 article_id；block_type 区分。
2. 检索怎么组合？  
   - dense bge-m3 + BM25 sparse，RRF(k=60)，rerank；Recall@8 1.000，MRR 0.958。
3. 怎么防幻觉？  
   - claim-first、citation 必须在证据集、quote 可定位、数字/日期/版本/受众覆盖、语义核对、失败关闭。
4. LangGraph 解决什么？  
   - revise/clarify/flow 路由/多轮状态；有上限，不无限循环。
5. 流程事实怎么保证？  
   - YAML DSL、三值谓词、DAG、closed/partial；Advisor 不写 checklist 事实。

## 3. 指标与失败（8 分钟）

1. W6-B 评测和生产为什么两个数字？  
   - 评测 ultraspeed 92.7% / p95 43.6s；生产 vPro 97.8% / p95 174.4s；不同 run。
2. W7 为什么失败？  
   - remediation4 质量门禁过（support 1.000、answer 0.875、version 1.000），p95 21.38s 超 10s；总门禁未过。
3. W3 的 75% 和 W6-A 的 98.1% 怎么解释？  
   - baseline 不改；W6-A 是同 20 题 prompt remediation；两个数字都保留。
4. 你最大的失败是什么？  
   - 生产 vPro 长尾 174s，现场演示不可用；W7 延迟未过；W9 因网络没做。

## 4. 工程与合规（5 分钟）

1. 为什么用 MCP？  
   - 检索/元数据只读工具化，应用不直接读 Qdrant/YAML；contract test + 失败信封。
2. Docker 一条命令怎么启动？  
   - app + Qdrant，preflight 检查 data/manifest/points/`.env`；模型缓存挂载；首次下载 4.4GB。
3. 数据合规？  
   - 公开页面/附件，不用登录页/个人名单；本地快照；引用回官网；PII 脱敏。
4. 如果公开部署？  
   - 反向代理、鉴权、限流、预算熔断；W8 只做本地 demo。

## 5. 行为与反思（5 分钟）

1. 讲一次你做错的设计。  
   - 例：W6-B 曾把页面展示档和真实模型解耦；后来改成 UI 不展示模型、评测/生产分档记录。
2. 讲一次你拒绝的做法。  
   - 拒绝把 W7 冻结集改掉/复用旧标签；拒绝把 vPro 结果写成 ultraspeed。
3. 下一步？  
   - 延迟优化、W7 答案覆盖、开源 PR（W9 deferred）。

## 评分表（1–5）

| 维度 | 5 分标准 |
|---|---|
| 30 秒 | 4 句内说清问题/做法/数字/失败 |
| 技术 | 能解释条款切分、引用校验、流程 DSL 的取舍 |
| 指标 | 每个数字带 run/模型/测试集口径 |
| 失败 | 主动说 W7/W9/延迟，不洗白 |
| 反问 | 能问出团队 RAG 评测/数据更新/人工入口 |

## 红旗回答

- “W7 通过了” → 立即纠正；W7 总门禁未过。
- “97.8% 是评测主结果” → 这是生产 vPro；评测 ultraspeed 92.7%。
- “W9 已 merged” → 没有；deferred。
- “模型全自动判断资格” → 流程/资格由 YAML/规则，LLM 只解释。
- “所有回答都能保证正确” → 只保证引用/核对通过；不保证政策解释绝对正确。
