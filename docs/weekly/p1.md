## 1. Section-aware 证据选择

新增 `retrieval/section_select.py`：

- 表格 section 检测：管道符/制表符、表格行、数字占比、课程表关键词；
- 叙事 section 加分（培养目标/培养要求/毕业要求/专业核心课程/主干学科/学制/学位）；
- 宽问题（如“培养方案”）默认最多保留 **2 个表格 section**，其余表格写
  `TABLE_SECTION_DEPRIORITIZED` warning；
- query 明确包含“课程/学分/学时/计划/进程/矩阵”等词时放开表格上限；
- 只在 rerank 模式应用，不改 RRF/检索召回与 W3 核对。

## 2. 生成重试

- **JSON 修复空返回**：第二次修复仍为空时，追加一次“只输出合法 JSON / 无答案输出
  `{"claims": []}`”的重试；非空但非法 JSON 不重复重试；
- **空 claims**：第一次 `{"claims": []}` 后再问一次“证据确有支持则给 1-5 条，
  否则保持空”；仍为空则接受拒答，不强行生成；
- 两个重试均有 trace 字段：`json_empty_retried`、`empty_claims_retried`、
  `empty_claims_error`；
- 重试失败不改变 W3 的 `NO_VALID_CLAIM` / `GENERATION_FAILED` 语义。

## 3. 版本意图

新增 `qa.guard.check_version_intent`：

- 只在用户提供 `intake_year` 且问题含“培养方案/版本/版/届”时判断；
- 问题年份（如“2022 版”）与入学年份（如 2024）不一致 → `VERSION_MISMATCH`，
  在检索前拒答，并给出“请改问 2024 版”的明确说明；
- 无 profile 或年份匹配时不拦截；不误伤“2022 年奖学金标准”等日期问题。
