## 1. 本周做了什么

W3 v1 在 rendered 支持率 75%、blocking/PASS 契约不一致、中文数字漏检和
AI 预标注问题上未达门禁，已整体回退。本周按 v2 设计**测试先行**重建：

1. **契约层**：`IssueScope` / `IssueSeverity` / `VerificationDecision`
   （PASS/PARTIAL/ABSTAIN）/ `VerificationIssue` / `VerificationResult`；
   `PASS` 与 `CLAIM+BLOCKING` 互斥，`PARTIAL` 必须保留 claim 且
   `dropped_claim_ids` 非空。
2. **引文 span 层**：`normalize_with_map` + `locate_quote`；
   `Citation.quote_start/end` 从“归一化偏移”迁移为 `article.text`
   **原文偏移**，支持空白、全半角、弯引号、零宽字符、跨行和多 part。
3. **Fact 层**：百分比、日期/年份、期限、金额/学分/学时、区间；
   覆盖中文数字（`十万`、`两万元`、`连续两年`、`二〇二五年九月一日`）、
   全半角与 `2025-09-01` 等价形式；无法可靠规范化的中文数字记录为
   `unparsed`，不猜测、不强行拦截。
4. **Scope 层**：H5 受众、H6 状态/生效区间/冲突/混合版本、H10 输出隐私；
   所有 scope 问题为 `EVIDENCE+WARNING`，全部剔除才拒答。
5. **废止探针**：主检索为空时，用 `status=[repealed]` 再做一次无 LLM
   检索；命中 `ONLY_REPEALED`，未命中 `NO_EVIDENCE`；探针耗时单列。
6. **Verifier**：H1/H3/H4/H7/H10 的 claim/citation issue、claim 丢弃与
   `PASS/PARTIAL/ABSTAIN` 决策；`PARTIAL_ANSWER` 只渲染通过 claim，
   固定提示“部分结论未通过引用核对，已省略；以下仅为可核实内容。”。
7. **服务/UI/trace**：新增 `PARTIAL_ANSWER`、`UNVERIFIABLE`、
   `ONLY_REPEALED`、`VERSION_MISMATCH`、`VERSION_CONFLICT`；
   trace 记录 `verification`（decision/issues/scope_issues/dropped IDs/
   partial/reason_code）与 `repealed_probe`；UI/CLI 显示 partial、
   issue 类型、丢弃 ID、探针耗时。
8. **评测**：`w3_run.json` 快照、`w3_support_labels.jsonl` 人工标注模板、
   `w3-dev-report.{json,md}`；记录 git commit/dirty、模型、向量 manifest
   hash、config hash、warm/cold、run hash；报告含结构门禁、draft/rendered
   support、拒答混淆矩阵、误拒率、partial 率、issue 分布与错误归因。

### 4.1 标注操作（本轮已完成，保留供 W6 复标）

推荐用交互式 CLI，一次只处理一条，并在每次选择后立即写回：

```bash
# Windows 终端若中文乱码，先 chcp 65001，或用 Windows Terminal
.venv\Scripts\python.exe scripts\label_w3.py --annotator yaukin
# 或
make label-w3 ANNOTATOR=yaukin

# 只看进度
.venv\Scripts\python.exe scripts\label_w3.py --status

# 生成 Markdown 核对表（不写标签，便于通读）
.venv\Scripts\python.exe scripts\label_w3.py --sheet
# 或
make sheet-w3
```

CLI 会显示问题、claim、`located_quotes`（渲染时真正使用的 quote）、
`issues` 和 `fact_uncovered`；按 `s` / `p` / `u` 记录，按 `k` 跳过，
`q` 保存退出，`?` 查看口径。每次选择后可写一条可选 note；脚本自动写入
`annotator`、`labeled_at`，不会替人判定。

`--sheet` 默认拒绝覆盖已存在的核对表，避免抹掉本轮人工勾选/note；W6 新
run 需要新表时请换 `--sheet-output` 或显式加 `--force-sheet`。

判定口径（严格引文级，只看 quote 文本）：

1. quote 是否直接陈述 claim 的**主要事实**？否 → `unsupported`；
2. 数字、日期、条件、范围是否一致？是 → `supported`；
3. 主要事实一致，但 claim 多了关键条件/范围/第二个断言，或措辞强弱
   不一致 → `partial`；
4. quote 与 claim 的主要事实矛盾 → `unsupported`。

不看条款上下文、不看问题、不补外部知识；`partial` 不等于失败，是正常的
中间标签。

```bash
make eval-w3-report
```

提示词/重写改进，或由用户明确接受例外；**不得改阈值或伪造标注**。

## 6. 下一步：W6

按 v2 设计，W3 不通过后进入 W6；建议分两小步，不要把重写循环一次做全：

1. **W6-A 提示词收紧（先做，不加 LLM 调用）**：
   - claim 只复述 quote 已有事实，不得补条件、后果、范围、版本、条号或
     评价性概括；
   - quote 必须覆盖 claim 的完整“条件 + 后果”；否则选更长的连续原文，
     或把 claim 缩短到 quote 能支持的范围；
   - 保留“一般/原则上/可以/应当”等限定词，不得强化/弱化；
   - 列举多项时，quote 必须包含各项原文；否则只保留 quote 明确写出的
     引用关系，不展开；
   - 跑同一 20 题，观察 rendered 支持率是否达到 85%。
2. **W6-B 语义检查/重写循环（若 A 不足）**：
   - 每题一次批量 LLM 调用，对 claim/quote 判 supported/partial/
     unsupported；partial 时重写 claim 或换更长 quote，最多 1 轮；
   - 重写后仍不过确定性校验或仍 partial 的 claim，落到
     PARTIAL/UNVERIFIABLE，不进入答案；
   - 记录 verdict/rewrite 到 trace，控制额外延迟与 token。
3. **复标策略**：W6 生成新 run 后旧 labels 失效；对未变化的
   `(claim, located_quote)` 可沿用旧标签作为 prefill，但 `annotator` 留空
   等待人工确认；最终门禁只算人工确认标签，不得把旧 56 条直接套到新 run。
4. **验收目标不变**：结构门禁 100%、rendered 支持率 ≥85%、拒答召回 ≥80%、
   误拒 ≤20%；p50/p95 记录，探针单列。达不到就继续 W6 或由用户明确接受
   例外，不改阈值。
5. W4：MCP、sparse/rerank、完整 audience/version 解析；复用本轮
   `VerificationIssue`/`VerificationResult` 契约。
