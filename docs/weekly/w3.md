## 实现口径与设计差异

1. **quote span 语义迁移**：W2 的 `quote_start/end` 是 `text_normalized` 偏移，W3 起是 `article.text` 原文偏移。UI 高亮、人工复核直接用原文 span；多 part 条款相对被引 part 的 `article.text`。
2. **H1/H3/H7 复用而非复制**：`DeterministicVerifier.verify` 内部调用 W2 `ClaimValidator`，把其 `dropped`/`dropped_citations` 记录转换为 `VerificationIssue`（`NO_VALID_CITATION` 对外映射为 `MISSING_CITATION`），W2 校验行为不变。
3. **`NO_VALID_CLAIM` 收窄**：W2 中“有 claim 但 quote 全部失败”也返回 `NO_VALID_CLAIM`；W3 判定树把它归入 `UNVERIFIABLE`，`NO_VALID_CLAIM` 只表示模型零 claims。W2 服务测试已同步更新。
4. **版本检查按证据逐条处理**：`check_scope` 中个别证据状态/区间不符 → 记 `VERSION_MISMATCH` blocking 并剔除；仅当全部证据被剔除才整题拒答。这与设计 8.1 判定树的“状态/区间不符 → VERSION_MISMATCH”在“全部不符”时一致，部分不符时更保守（保留可用证据作答而非整题放弃），已与“全部 claim 失败才 UNVERIFIABLE”的语义对齐。
5. **fact 覆盖宁可漏检不可误杀（设计 5.4）**：只抽带单位/百分号/日期结构/期限的数字；覆盖匹配接受中文数字、量词、区间连接符与日期跨格式变体；无法生成可靠匹配形态的 fact 按“未覆盖”处理（拒绝放行），但这类 fact 在抽取端就被排除，不进入核对。
6. **`PARTIAL_INCOMPLETE` 归因**：设计 10.4 列出该主因；实现中 expected=ANSWERED 且 outcome=PARTIAL_ANSWER 不算失败题（partial 率单独报告），`PARTIAL_INCOMPLETE` 仅当人工复核认定 partial 丢失关键结论时使用——20 题自动归因不会产生该值。
7. **超出 5 条 claim 记为 warning**：W2 的 `TOO_MANY_CLAIMS` 是裁剪而非核对失败。W3 仍不渲染第 6 条及以后，但 issue 记为 warning，不触发 `PARTIAL_ANSWER` 的“未通过核对”提示（首次 live 运行中 d001 因此被误标 partial，已修正）。
8. **版本冲突 v0 收窄为“生效日平局”**：首次 live 运行中 d013/d014 命中 `info-ug-math-plan` 的 v2022/v2024 两个 active 版本，被判 `VERSION_CONFLICT` 拒答。语料有意把不同年级培养方案都标 active，属“届别版本”而非竞争版本；W3 改为仅当同一 doc 多版本 `effective_from` 相同（无法裁决）才 `VERSION_CONFLICT`，生效日不同的多版本保留并记 `MIXED_VERSIONS` warning，完整解析留 W4。
9. **run 快照含 claim 级 citation**：`QAResult.draft_claims` 记录每条 draft claim 的 `article_id + quote`，供人工标注与误杀复核；`eval_w3.py --reuse-run` 可直接复用快照重算报告，避免标注阶段重复调用模型。

### 代码复审与微调（2026-10-23，live 复测后）

对 W3 全文做了一轮逐模块复审，用失败测试确认后修复：

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | `normalize_with_map` 遇到零宽字符时仍向映射追加空串 | 归一化映射整体错位，quote span 指向错误原文字符 | 空片段跳过；补零宽字符/前导零宽测试 |
| 2 | H10 复用 `redact_text` 全量计数，把“联系人：X”也判隐私 | 公开条款中的联系人姓名导致 claim 被误删（超出设计 6.4 四类范围） | 只保留 `id_card/mobile/student_id/personal_email` 四类；补测试 |
| 3 | 显式请求 `Audience.ALL` 时被当作具体受众去匹配 | 请求“全体”反而全部证据不匹配 → 误拒 | `ALL` 视为未指定，仅提示；补测试 |
| 4 | 区间事实不支持量词：`3-4个学期` 只抽到 `4学期` | 区间下界失去保护（上界仍拦得住） | 区间单位加 `个学期/个学年/个工作日`，canonical 去“个”，覆盖变体容忍“个”；补测试 |
| 5 | 废止探针耗时混入端到端 p50/p95 | 与设计 6.3“探针单列”不符 | `QAResult.probe_ms` + 报告剔除探针并单列；旧快照无此字段，报告如实注明 |
| 6 | 标注脚手架按 (题目, 文本) 去重，重复 claim 无法分别标注；rendered 匹配用集合 | 重复文本的第二条 claim 变 unlabeled / 被误标为已渲染 | 脚手架写 `occurrence` 序号，加载器优先用显式序号；rendered 用计数器逐条消耗 |
| 7 | citation 去重键缺 `part_no` | 与“片段身份是 (article_id, part_no)”不一致 | 去重键补 `part_no` |
| 8 | 日期覆盖只认非零填充/斜杠格式 | `2025年09月01日` 被误判未覆盖 | 补零填充、点号格式变体；补测试 |
| 9 | 标注文件未校验 run hash | 快照更换后标注可能被静默套用 | 报告前比对 `run_sha256`，不一致告警 |
| 10 | 非法标注值（非 supported/partial/unsupported）不进任何桶 | 支持率分母静默变小 | 非法值归入 unlabeled；补测试 |

以上修复不改变 live 结果的结论：旧快照未含 `probe_ms`，重算报告的支持率/拒答指标不变（75.0% / 100% / 7.1%），报告中已注明探针计时从下一次运行起单独记录。复核同时对快照做了审计：rendered citation 的原文 span 全部对齐（0 个 `span_ok=false`），快照无手机号/身份证。

**rendered 支持率未达 85% 的主因是引文过窄，不是数字误杀**：按“严格引文级”口径（用户确认），d005 的 5 条引文只截取第八条情形列举项（“给予开除学籍处分”在条款引导句），d008 的 5 条引文只截取条件项（“申请励志奖学金应同时符合…”的匹配句未入选），这 10 条记 partial；d003 省略“一般”、d009 只引条件编号、d010 省略“除开除学籍处分外”各记 1 条 partial。若按“条款上下文可补足”口径，这 10 条可判 supported，rendered 支持率为 94.2%——口径差异已在报告中注明，W6 用重写/提示词改进引文跨度。

**d006 是唯一的误拒**：模型把问题里的“一学期内”写进 5 条结论，但引用只截取“累计旷课10—19学时…”等区间句，H4 按 quote 覆盖判全部失败 → `UNVERIFIABLE`。原文第十六条确实含“一学期内”，属“引文过窄 + 模型补全上下文”的组合，不是抽取误报；W6 语义核对/重写可修，W3 保留严格口径。

**标注状态**：`data/eval/w3_support_labels.jsonl` 57 条标注为 Qoder AI 预标注（`annotator=qoder-ai-preannotation`，严格引文级口径已由用户确认），仍待逐条人工抽检后才能称为正式人工标注；报告与本节均按“预标注”记录。

### 复跑方式

1. `make eval-w3` 重跑 20 题并写 `w3_run.json`；
2. `python -m uv run python scripts/eval_w3.py --reuse-run --write-labels` 从快照生成标注脚手架（不重复调用模型）；
3. 标注后 `python -m uv run python scripts/eval_w3.py --reuse-run` 重算报告。

## 已知限制与风险

| 限制/风险 | 影响 | 当前处理 |
|---|---|---|
| fact 抽取启发式 | 可能漏检（不拦）或极少数误拦 | 设计 5.4 口径：宁漏勿误；报告披露误拒归因；W6 语义核对补强 |
| 版本冲突只在 Evidence 内检测 | 未召回的冲突发现不了 | 报告披露；W4 接版本解析器 |
| 受众仅显式请求时硬检查 | 未指定受众可能混合条款 | 仅 `AUDIENCE_UNDETERMINED` warning；W4/W5 接追问 |
| p95 抖动（W2 遗留） | 延迟不稳定 | W3 未新增 LLM 调用（探针无 LLM）；沿用 W2 豁免记录，不声称 p95 达标 |
| 20 题单标注人 | 支持率不可外推 | 报告标注“开发集方向性证据”；W7 冻结 50 题再报区间 |
| rendered 支持率 75%（严格引文级） | 未达 85% 门禁 | 主因是引文过窄（d005/d008 各 5 条）；条款上下文口径为 94.2%；W6 重写/提示词改进引文跨度，不靠放宽标注过关 |
| 支持标注为 AI 预标注 | 尚不能称“人工标注” | 用户已确认严格引文级口径；逐条抽检后再更新报告标注人 |
