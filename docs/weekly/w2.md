14 道可答题全部返回引用答案，6 道非可答题全部返回预期原因码。p95 失败来自第三方模型抖动：一次 `d011` 的 LLM 调用耗时 151s，另一次 `d001` 30.7s（含一次 JSON 修复）；不是检索或校验耗时。W2 的核心验收「引用真实、零编造」通过，延迟门禁需要在 W4/W7 换更稳定的端点或加超时/重试策略。W2 不报告答案正确率。

p50/p95 的实际口径是 **warm**：`eval_w2.py` 先 `service.warmup()` 再计时；UI/CLI 启动时也会预加载 bge-m3，避免首问承担模型加载。冷启动预热单独记录（本机最新 27.4s，随磁盘/缓存波动），不能把它混入 p50。严格 part_no 指标也已启用：引用 ID 与 quote 定位都按 `(article_id, part_no)` 统计，最新报告 `part_no` 错误 0。

模型选择：先测了 `.env` 里的 `mimo-v2.6-pro`（单次 15–24s，p95 更差），再测 `mimo-v2.6-flash`（23s）与 `mimo-v2.6-pro-ultraspeed`（约 3.3s，JSON 合规），最终按用户选择把 `.env` 的 `ADVISOR_MODEL` 改为 `mimo-v2.6-pro-ultraspeed`。

## 关键实现口径

1. **片段身份是 `(article_id, part_no)`**：同一 `article_id` 可能有多个 part；Evidence、Citation、去重与 trace 都保留 `part_no`，对外展示仍以 `article_id` 为主。
2. **`article_id` 只在被引条款内唯一**：LLM 只输出 `article_id + quote`，quote 在哪个 part 命中就补哪个 `part_no`；引用 ID 必须来自本轮 Evidence。
3. **默认 article-only**：`PolicyFilters.block_types` 默认 `[article]`；section 只通过显式参数/评测子集启用，单独统计 `section_recall@8`。
4. **低置信日期不隐藏**：16 个版本的 `date_confidence=low` 进入引用卡片提示；历史问题在 W2 直接 `HISTORICAL_NOT_SUPPORTED`。
5. **失败关闭**：无证据、生成失败、无有效 claim、索引不可用都不输出半截答案。

## 已知限制与风险

| 限制/风险 | 影响 | 当前处理 |
|---|---|---|
| 第三方模型 p95 抖动 | p95 16.3–36.8s，未达 10s 门禁 | 如实记录；核心引用门禁通过；W4/W7 评估更稳定端点或超时/重试策略 |
| Docker Hub 直连超时 | 无法直接拉取官方镜像 | 使用国内镜像拉取后重新 tag 为 `qdrant/qdrant:v1.19.1`；`compose.yaml` 仍使用固定 tag |
| HuggingFace 直连超时 | 模型下载失败 | 使用 `HF_ENDPOINT=https://hf-mirror.com`；下载完成后可 `HF_HUB_OFFLINE=1` |
| 本机无 CUDA 版 torch（初始） | CPU 索引约 80 分钟 | 安装 cu128 wheel 后 GPU 索引完成；`vector_manifest.device` 记录实际设备 |
| 阈值为 dev_v0 校准 | 可能过拟合 20 题 | 阈值写入配置并注明来源；W4 用更大开发集重校准 |
| `section` 异质 | 教师页/新闻目录不适合作为条款 | 默认 article-only；dev section 只选培养方案结构页 |
| 受众歧义 | 未指定本科/研究生时可能同时返回两类条款（如 d001） | UI 下拉可过滤；W2 开发集未覆盖追问受众；W3/W4 再决定是否追问 |
| 教师名录含公开联系方式 | 引用卡片可能带个人信息 | W2 默认 article-only，不展示 section 联系方式；W2 不扩大 `redact_contacts:false` 范围 |
| 答案质量未评估 | 不能对外声称问答准确率 | README 与报告均注明 W2 只证明引用真实；W3/W7 再评答案 |
