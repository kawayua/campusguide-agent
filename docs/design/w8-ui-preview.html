W8 UI 设计规范

评审版 · 对照 2026-10-25-w8-demo-docs-design.md 第 3 节

布局 状态语言 清单 引用 澄清 / 拒答 进度 / 延迟 调试脱敏 实现映射 边界
评审请重点看 5 个决策：
1. 三栏工作台：历史在左、对话居中、结果在右；输入永远贴底；点击历史打开右栏；
2. closed 仍用 ANSWERED，另加“批次已截止”状态，不新增 outcome code；
3. 流程回答在对话区显示结构化摘要，完整 Finalize 原文折叠，清单只放右栏；
4. 引用分两类：claim 逐字 quote 与流程条款定位，后者明确标注“无逐字 quote”；
5. 澄清选项同时出现在消息内和输入框上方（仅最后一轮），避免滚动后找不到操作。

00三栏布局

参照 Qoder 的冷色极简工作台：左栏承载历史，中栏只承载当前对话，右栏承载结构化结果。输入框固定在中栏底部，不随消息滚动。

左 · 历史新对话、搜索、今天/昨天分组；点击任意会话，中栏加载并自动打开右栏。
中 · 对话标题 / 轮次 / 状态在顶；消息滚动；输入、示例、隐私提示贴底。
右 · 结果清单 / 引用 / 调试；可收起，收起后中栏自动变宽；点击会话会重新打开。
  • 新对话：不继承上一段上下文，右栏收起；首次提问后标题取问题前 18 字。
  • 会话切换：同一 session 串行发送；处理中禁止切换，避免串线。
  • 移动端：左历史与右结果改为抽屉；输入仍贴底；点会话/结果按钮打开右抽屉。
  • 字体（已确认）：正文保持无衬线；品牌名、会话标题、右栏标题、步骤标题、引用标题使用 STSong → Source Han Serif SC → Noto Serif CJK SC → Noto Serif SC → Songti SC → serif 的衬线栈，和风格探索 A 一致。STSong 为系统字体，不打包进仓库；跨机器由后面开源宋体回退。
  • 刷新保留（已确认）：实现时用 localStorage 保存会话列表、当前会话与结构结果，同一浏览器刷新后恢复；不跨设备、不写服务端。
  • 历史只存会话摘要：不把完整聊天原文写日志；调试只留 trace_id / outcome / 脱敏 query。

01状态语言

状态徽标必须同时给颜色和文字，颜色不是唯一信息。主 outcome 只来自 ConversationReply.outcome；flow 的 closed 是独立状态。

outcome界面文案处理
已核实回答ANSWERED展示 claims / checklist；若 closed，另加批次徽标
部分回答PARTIAL_ANSWER区分 claim 被省略 / 流程未确认；只展示已核对内容，未确认项显式标注
需要补充信息CLARIFY展示问题、why、选项、跳过；最多 3 次
未作答 · 原因ABSTAIN / NO_EVIDENCE / UNVERIFIABLE / GENERATION_FAILED / TOOL_UNAVAILABLE 等不展示 claims；显示缺什么、下一步、handoff
未作答INVALID_REQUEST / OUT_OF_SCOPE 等可操作提示，不显示堆栈
批次已截止flow.status = closed独立于 outcome；禁止“现在去办”，不推断下一年日期
部分回答 · 未确认项已标注 需要补充信息 未作答 · 涉及个人信息 本批次已截止 历史版本不支持
semantic_unchecked banner：本次未完成语义核对，仅硬校验通过。该提示固定显示在答案上方，不能隐藏。

服务未就绪 / 索引不可用 / MCP 超时：显示可操作提示（启动 Qdrant、配置 .env、检查 manifest），不显示堆栈；失败最多给 1 次重试提示。

02办理清单

  • 默认隐藏 not_applicable，调试开关可显示；顶部摘要只统计可见项。
  • closed 必须显著：左侧红色标线、状态徽标、截止说明；不显示“现在去办”，不推算明年日期。
  • 排序：保持 YAML / 流程顺序，不按状态重排；用顶部筛选聚焦“已截止”“可办理”等状态。
  • 卡片字段：标题、状态、description、材料、deadline / deadline_note、负责部门、status_note / blocked_reason、依据条款。
  • 依据折叠：流程 citation 是 article ID，界面解析为“文档名 · 条款号”并链到官网；不显示 text_raw_ref。
  • 空状态：CLARIFY 时用中文标签显示缺少的信息，不暴露内部 slot 名；拒答时显示“本轮没有办理清单”与 handoff。

03引用与结论

  • claim 引用：文档标题、条款号、块类型、逐字 quote、来源 URL、date_confidence=low 提示。
  • flow 引用：checklist 只携带 article ID，没有 quote；界面明确标为“流程条款 · 仅条款定位”，不伪装成逐字引用。
  • 定位：答案中的 [文档 条款] chip 点击后切到“引用”tab，滚动并高亮对应卡片。
  • 不展示：MCP payload、原始 HTML、text_raw_ref、内部打分（打分只在调试面板）。
  • 链接直连：来源 URL 直接打开学校官网，不经过本系统代理。

04澄清与拒答

  • 有 allowed_values → chips，点击即发送；没有 → 使用输入框。
  • 显示 why：来自 slot why_needed 或 clarification reason，让用户知道为什么问。
  • “跳过”发送“跳过”，走 declined 路径；不把跳过当作默认值。
  • 最多 3 次；超限后给通用路径 + handoff，不继续循环。
  • 拒答：只显示 reason 的用户文案、缺什么、handoff；不显示未核实 claims，不自由发挥“建议你……”。
  • 隐私：不回显输入中的敏感内容；日志只留脱敏 query、trace_id、outcome、耗时。

05进度与延迟

  • 只流式节点进度：planner → flow / retriever → advisor → verifier → finalize；不流式输出未核对答案 token。
  • 每个节点可显示耗时；超时显示当前节点与已耗时，不显示假的“即将完成”。
  • 交互目标（演示档）：p50 ≤ 15s、p95 ≤ 45s；单请求上限 120s，超时 fail-closed，不返回半成品。
  • 演示档 ultraspeed 与评测档 vPro 在顶部固定标注，不混指标。
  • vPro 已知 p95 174.4s，若坚持用 vPro 演示，页面提示改用录屏；不隐藏限制。

06调试与脱敏

调试 tab 默认折叠，面试时可展开；只保留可解释链路，不输出密钥和隐私。

Plannerplanner_source、intent、flow_id、query plan、warnings
Retrievalarticle_id、rank、分数、matched query、index_version
Verifierhard issues、semantic labels、decision、revise / clarify 次数
Finalizeoutcome、reason、citations 数、checklist 数、handoff
Timing节点耗时、总耗时、模型名、prompt 版本、trace_id
禁止展示：API key、.env、完整系统提示词、用户隐私原文、text_raw_ref、原始 MCP payload。

08边界与不做

  • W6：不改图、模型默认、评测口径；W6 评测仍 vPro。
  • W7：冻结集 / 标签 / 报告不改；README 同时展示 W6 通过与 W7 failed，不混写。
  • 不做：历史版本、跨学校、个人成绩/学号查询、文件上传、公开多租户、答案缓存。
  • 限流：每 session 每分钟 10 次；可选 DEMO_DAILY_REQUESTS；不做无限排队。
  • 移动端：左历史 / 右结果改为抽屉，输入仍贴底；调试仍默认折叠。
  • 审核后：按此稿落 Gradio view-model + fake runner 测试，再接真实图；Docker/CI/README 留到后续步骤。
