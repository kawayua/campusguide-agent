# CampusGuide 答案质量修复方案

日期：2026-10-28。状态：待实施，本文只制定方案，未修改业务代码、模型、语料或索引。

依据：`data/eval/corpus_random_100_fixed/report.md`、`review.jsonl`、`summary.json`及最终全量运行`final_20261028/results.jsonl`。以现有Planner、Retriever、Advisor、Verifier、Finalize链路为基础分批修复。

## 目标与基线

本轮100题语料核对：27题完整回答、45题部分回答、19题有据未答、4题召回失败、3题实质错误（适用对象不当、答非所问、时间判断错误各1题）、1题合理拒答、1题指代歧义。系统ANSWERED有34题，不能直接作为正确数。

API调用失败和INDEX_UNAVAILABLE均为0；127条最终引用的ID、文字和偏移校验无异常；675项离线测试通过。当前主要瓶颈是证据相关性、问题覆盖和证据上下文。现有27题是单轮完整结果，尚不能据此声称稳定达到27%的准确率。

质量目标：完整覆盖用户所问的对象、方面和列表，适用范围与日期正确，全部事实可追溯；证据不足时具体说明缺口，必要时澄清。答案措辞和原有系统状态不作为唯一验收依据。

建议发布门槛：原100题“完整回答+有依据的合理拒答+必要且正确的澄清”达到85题及以上；额外20题泛化集达到16题及以上。以上为建议验收目标，须实施后实测，不是已实现结果或成功率承诺。事实、年份、身份和引用错误另设硬门槛，不能靠增加拒答凑达标率。

## 修复约束

- 保留当前模型、业务as_of=2026-10-25、知识库快照与向量索引版本，用同一口径判断代码修复收益。实际测试日期另行记录。
- 不硬编码原题答案、人名、课程名单或题号；组织专业词典、原文目录、名册和表格是通用结构化依据。
- 初期利用现有JSONL和Qdrant构建可追溯的派生索引，无需重建4026条向量。发现某类源表解析缺失后再局部修复与增量更新。
- 不以全局降低重排阈值、跳过语义核对、增加无限重试来提高完成数量。阈值如需调整，应在独立正负样本上校准。
- 将“补检索”和“修复引用”分别计数，各有上限。超出预算时返回已核实内容及具体缺口。
- 675项现有离线测试是兼容性基础，新增测试必须验证可观察的错误行为，并包含错误专业、错误年级、相似人名和不相关材料等反例。

## 先建立验收数据：阶段A

现有review.jsonl用于定位，不等于已标全所有答案要点。开始业务改动前，为100题补齐问题级与事实级验收数据，冻结版本和哈希。

每题记录：问题单元、必须回答的对象/方面、必要事实或列表、适用身份/届别、允许使用的文档版本、具体article_id与part_no、连续原文依据、允许的拒答/澄清、禁止推断事项。对照关系复杂的题目，记录每个版本/对象对应的事实，不能只写“按原文回答”。

建议产物：`data/eval/answer_quality/gold_v1.jsonl`、`holdout_v1.jsonl`、`acceptance_manifest.json`。固定原100题文本和顺序；第100题保留原文，独立会话时把询问“两个学院”具体名称作为正确澄清，不私自改题。另增加明确院名的泛化用例。

标注规则：

- 第009题缺实验室完整总量，应说明证据和统计口径，不把科研平台数当实验室数。
- 第083题现有处分条款主要援引另一份申诉办法；具体申诉程序未在可用原文中得到支持时，应说明边界，不能把离校期限当申诉期限。经核实确实缺源文件后再定向补充语料。
- 第089题原问“发布了哪些公示”，两份公示事项均覆盖即可；公示期是另设检查项，不能事后追加要求来改判原题。
- 宽泛制度问题先明确必须覆盖的核心事项，不把所有相邻条款都当作必要答案；允许同义表达，不要求逐字匹配预写答案。

从当前完整题中建立27题回归保护集；另外冻结20题泛化集，覆盖不同专业与届别、名册归属、并列对象、日期排序、未知事实和含糊指代。泛化集不用于逐题调提示词，失败后继续调参需重新准备未见样本。

完成条件：100题均有可核对的检查项；原问题、事实依据和可接受边界对齐；空白标准答案不得被自动记作通过。

## 第一批：保留查询条件与对象，修复证据召回

### B1 结构化问题单元

问题单元与检索请求分开建模。问题单元表示用户希望知道什么，检索请求可以同时服务多个问题单元，不能把逗号切出的每一段直接当作独立问题。

在`agents/plan.py`增加向后兼容的问题单元契约，建议字段：

| 字段 | 用途 |
|---|---|
| unit_id / original_span | 稳定标识与原问题片段，追踪拆解来源 |
| subject / objects | 学院、专业、教师、奖项等明确对象 |
| audience_scope / cohort / version | 本科/研究生、入学届别、文件版本，分别表示，不混用 |
| requested_aspects | 核心课程、实践课程、申请条件、时间、负责人等 |
| answer_shape | 单事实、列表、比较、流程、计数、最新消息 |
| required_slots / ambiguity | 影响答案但缺失的条件及澄清原因 |

`planner.py`使用组织专业词典和问题中明确出现的实体补全子问题；LLM只辅助拆解，提出的实体与年份须能回指用户原文、已确认会话或注册表。比较题按对象继承各自条件，不能把2022和2024届别合并成单一过滤条件。

处理原则：

- “对于2024年入学的计算机科学与技术学生”是查询上下文，不是单独的问题。
- 同时问两专业或三教师时分别建立对象；共同询问的方面继承到各对象。
- “研究生工作由谁负责”描述查询对象，不等于提问人身份是研究生。
- 身份确实决定个人办理结果且未提供时澄清；明确要求跨身份比较时分别作答。
- 独立会话中“两个学院”“这个办法”无确定指向时先澄清，不猜对象。

改动范围：`agents/plan.py`、`planner.py`、`retriever.py`、`state.py`及相应trace；`Clarification`如新增实体歧义原因，需要同步客户端展示与会话回填。

### B2 召回与证据排序

在现有混合召回和重排基础上，增加对象一致性及任务相关性检查：培养方案匹配专业与届别；招生题保留招生/复试主题；委员会负责人题优先组织/委员会名录，而非包含同名词的解释部门条款。只有来源元数据足够可靠时才使用硬过滤，无法确定的条件作为排序和告警，避免错误排除材料。

保留规范化姓名与原文的映射用于检索和匹配；不能因“梁 云”排版空格漏掉“梁云”，也不能把两个相邻姓名拼成新姓名。无法可靠判断名册项边界时补查其他直接师资来源或说明不足。

阈值边界题先检查是否召回正确文档及完整主体，再在独立样本上评估阈值。不能为让第039题越过0.60而普遍放宽所有低相关候选。

定向题：001、002、017、027、028、039、043、053、068、091、096、100。

完成条件：017保留“2024+计算机科学与技术”；028不以奖学金评分代替复试规则；053命中三委员会负责人名单；002不把研究生政策当本科通用规则；100正确澄清。使用其他专业、其他年级和不相关同名词重复验证。

## 第二批：表格、名单与长条款的证据完整性

当前Hybrid与Graph都有预算裁剪，且Graph每文档默认最多3条证据。需要先把目标证据选完整，再用剩余预算补充相邻材料。

实施内容：

1. 在`hybrid.py`、`section_select.py`、`agents/retriever.py`统一预算计量口径，把正文、必要标题和表头一起计入。避免一层按字符、一层按估算token导致关键片段过早淘汰。
2. 按问题单元建立证据配额。课程列表优先对应课程模块；实践要求优先实践/毕业设计；对照题为每对象和版本保留直接证据。矩阵和无关教学表只占补充预算。
3. 对表格保留原始行顺序、模块边界、表头、课程名、课程代码、学分及适用版本。跨分片时取必要的相邻片段，不把上一模块学分要求套到下一模块。
4. 建立可重建的表格/名册派生视图，所有条目回指原始doc_id、version_id、article_id、part_no及原文偏移。结构化抽取失败时退回原文，不把抽取结果伪装成原文quote。
5. 证据需要裁剪时保留连续原文窗口与起始偏移，不拼接不相邻句子，不改变引用定位的基准。
6. 记录候选、排除原因、保留片段、各问题单元缺失项，能够回答“正确片段在召回、重排还是预算阶段丢失”。

定向题：003、017、020、031、035、047、061、064、065、076、077、080、097。

完成条件：017五门方向理论课全部覆盖，即数据分析与数据挖掘、人工智能、深度学习、文本挖掘与分析、计算机视觉与图像处理；实验课另列，其他模块不混入。003/076实践课程、020毕业设计形成有依据的回答；031/065对照证据不串届别。发现源PDF解析本身丢失表头时，只修对应解析器和受影响文档，记录变更哈希并重跑依赖题。

## 第三批：生成覆盖与验证上下文

### D1 按检查项组织生成

Advisor接收已经规范化的问题单元和对应证据，减少其重新猜测题意。输出保留claims与引用，并标明服务哪些unit_id；不认识的unit_id拒收。对列表/程序题，需要列出证据支持的必要项或阶段，不能只给“符合条件（一）至（五）”或重复引导句。

核心改动：

- 生成前检查各单元是否有直接证据；无证据的单元单列缺口，不让无关片段凑覆盖。
- 为列表保存从原文确定的必要项集合；为比较保存“对象×方面”检查表。一个相关claim不等于整张表覆盖完成。
- 基础生成遗漏时，按遗漏单元最多增加一轮定向补检索/补生成。保留通过核对的既有claims，只核对新增或变化部分。
- 原问题单元初始建议上限12个，多个单元可共享查询；初始检索最多3次，定向补检索最多3次，保持有界。超过预算仍未覆盖时明确展示剩余部分。
- 问题单元和最终claim对应关系由规则及覆盖核对检查，不能只信模型返回的unanswered_questions。语义无法确定时标部分或待确认。

### D2 有边界地使用文档上下文

`build_evidence_block`及语义Verifier同时接收正文与可信来源上下文，但标明哪些是标题/章节、哪些是可逐字引用正文。

允许的上下文支持：同一可靠文档/章节的学院归属、名单所属系、表格列含义、文件适用对象。不得单凭文件标题或问题文字推断正文没有的金额、期限、课程、角色关系或未明确的成员身份。名册归属必须同时有正文中该人员的有效匹配，以及该名单明确的系/教师范围。

例如梁云的归属应由计算机科学与工程系教师名册标题和正文姓名共同支持；两个校外导师制度的第一/第二角色仍须各自正文支持，不因上下文放宽而对调。多来源结论显式保留各来源，不把多个quote拼成一个伪连续quote。

### D3 从最终保留内容计算完成状态

增加问题单元级覆盖结果：`answered / missing_evidence / generation_missing / verification_failed / clarification_needed`，并记录通过核对的claim或流程证据。

完整回答要求所有必要单元及其必要列表项均有已核对支持。流程清单只有在对应步骤/材料/期限与原问题一致且依据已验证时才计入覆盖。跨子查询得到的正确证据也可以覆盖该问题，不要求证据必须由同名query返回。

Finalize分别显示漏答、证据不足和核对失败原因；不再出现“已省略0条”，也不把已经由claim或有效流程回答的内容同时提示未回答。未知错误不能被无关流程的closed状态掩盖。

改动范围：`agents/advisor.py`、`agents/quote_repair.py`、`agents/verifier.py`、`verification/semantic.py`、`agents/state.py`、`graph.py`、`qa/finalize.py`。新字段提供兼容默认值，更新真实调用与错误路径测试。

定向题：014、016、019、022、029、040、042、053、054、055、062、068、074、083、087、091、099。

完成条件：014包含申请、审批和通知核心阶段；029/042解释具体条件而非条号；091答出所属系；016第一/第二导师不对调；062不因正文未重复学院名误拒；054/074/087已答部分不再被误报未答；任何遗漏都不能仅因相关证据非空而判完整。

## 第四批：日期、集合统计与证据边界

近期消息集合中的Article.published_at可能表示汇总文档日期，不能直接当作每条新闻发布日期；effective_from和采集日期也不能代替消息日期。

建立从现有汇总正文解析的消息条目视图，保存每条消息的published_on、title、original_url、所属学院/栏目及原文锚点。题目问“最近一条”时对可用收录集合按published_on取最大；问“某月有哪些”时按日期筛选整个可用集合，再回答集合内条目。只有完整遍历所声明集合后才能声称“共N条”“最新”；来源范围不完整时明确限定“知识库收录范围”。

人员、专业、基地等计数同样需要枚举依据或明确总量句；计算结果保留计数集合与去重依据。不从列举的科研平台推出实验室总数，不从局部名册推出全院人数。跨版本数据先按对象/版本划分，再分别计算。

定向题：009、034、056、072、081、082、087、090、095、098。

完成条件：095返回知识库2026-08-10消息及正确题名；090同时覆盖2026-10-10军训与2026-10-14党员培训消息；087只按9月收录集合回答；009继续不编造实验室总量。发布日期与举办日期不得互换。

改动范围：新增可追溯的消息/集合查询模块，MCP请求与响应如增加结构化字段需同步契约测试。初期不改原有向量payload；派生视图以源数据哈希校验缓存，源数据变化时失效。

## 配套：诊断、成本与接口兼容

为每题记录问题单元、实体条件、检索过滤、候选淘汰原因、证据选择、生成覆盖、最终覆盖、模型token与延迟。模型HTTP异常保存脱敏状态/类别；费用和认证异常不反复调用。测试连续基础设施错误达到3题即停止，恢复后另存运行记录，不混成内容质量结论。

新模型字段和派生数据都允许旧调用方读入；语义和覆盖验证失败时不得沿用上一轮通过状态。缓存键至少含问题单元、过滤条件、as_of、文档/索引哈希和提示词版本，避免跨年级或跨版本复用答案。

每批只运行受影响的离线测试和不超过8道代表性真实冒烟题；当批门槛失败先定位，不立刻消耗预算重复跑100题。最终才做完整评测，记录实际token用量，不预设未知API单价。

## 验收与交付

按A→第一批→第二批→第三批→第四批顺序实施。日期视图与标注可独立准备，但在最终结果中统一验证。每批单独保存变更说明、失败前后的最小复现和验收结果；尚未通过的项目不得写成已完成。

| 层次 | 验收要求 |
|---|---|
| 确定性回归 | 查询继承、对象/版本隔离、预算裁剪、标题上下文、日期最大值、计数、补检索次数上限、状态计算均有正反例，现有675项及新增相关测试通过 |
| 27题保护集 | 按核心事实检查，原有完整问题不因改动丢事实、换版本或出现新错误；允许合法改写，不能用字符串完全一致判定 |
| 原100题 | 按冻结标准逐项核对，分别统计完整、部分、错误、合理拒答、正确澄清；系统状态与内容标签分开 |
| 泛化20题 | 不包含只换人名却仍硬编码原答案的伪泛化；包含不同对象、错版本、缺事实、完整性和时间反例 |
| 稳定性 | 选002、016、017、034、053、054、062、074、091、095这10道关键题，各独立运行3次；其中1次可复用实施后的最终100题结果，另加20次。关键事实、范围、日期和必须覆盖项3次均须满足，不能挑最好一次计分 |
| 安全硬门槛 | 验收集中不出现编造引用、错学院/专业/届别、导师角色对调、错“最新”、把无依据总量写成事实；真实服务无API/索引故障，否则中止质量统计 |
