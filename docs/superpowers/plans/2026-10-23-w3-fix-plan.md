## 3. F2：Verifier blocking issue 与 decision 不一致

### 复现 A

一条 claim 有两个 citation：一个有效、一个无效。

```text
decision = pass
issues = [QUOTE_MISMATCH, severity=blocking]
claims = [c1]
```

无效 citation 被丢弃，但 claim 仍被保留；由于 `dropped_ids` 为空，`verify` 返回 PASS，尽管存在 blocking issue。

### 复现 B

Evidence 同时包含 active + repealed 条款：

```text
check_scope -> evidence=[active], issues=[VERSION_MISMATCH, severity=blocking]
verify      -> decision=pass
```

这是 [verifier.py](../../../src/campusguide/verification/verifier.py) 的决策逻辑只根据 `kept_claims` 和 `dropped_ids` 判断，没有把 `validation.dropped_citations` 与 `scope.issues` 的 blocking 计入结果。

### 决策

采用**claim-level blocking 与 evidence/citation warning 区分**：

- claim 级 blocking（无有效 citation、数字/日期不支持、隐私、空 claim、重复 claim）→ claim 不进入答案；
- 单个 citation 被丢弃但 claim 仍有有效 citation → `WARNING`，claim 可渲染；
- 单个 evidence 被 scope 剔除但仍有有效 evidence → `WARNING`，不把整题判 partial；
- 如果所有 claim 都被丢弃 → `UNVERIFIABLE`；
- 如果存在 blocking claim 且仍有其他 claim → `PARTIAL_ANSWER`。

如果团队选择更严格口径（任何 blocking 都 PARTIAL），也可以，但必须：

- `PARTIAL_ANSWER` 的 `dropped_claim_ids` 不能为空；
- UI 必须显示部分提示；
- 不得出现 `decision=PASS` + `issue.severity=BLOCKING`。

### 需要新增的测试

- 有效 citation + 无效 citation：claim 保留，issue 为 warning（或 decision 为 PARTIAL，按最终口径）。
- 全部 citation 无效：`UNVERIFIABLE`。
- active + repealed evidence：active 可渲染，scope issue 为 warning；全部 evidence 无效才拒答。
- 有有效 claim + 无效 claim：`PARTIAL_ANSWER`，只渲染有效 claim。
- `VerificationResult.issues` 和 trace 的 issue 集合一致。

## 4. F3：中文数字/日期覆盖漏检

### 已复现

```text
claim "连续2年"        vs quote "连续两年"              -> 未覆盖
claim "奖励2万元"      vs quote "奖励两万元"            -> 未覆盖
claim "2025年9月1日"   vs quote "二〇二五年九月一日"    -> 未覆盖
chinese_to_int("十万") -> 10010（应为 100000）
```

原因：

- `int_to_chinese(2)` 生成“二”，没有“两”变体；
- `_fact_patterns` 只覆盖部分中文数字；
- `extract_facts` 的日期 regex 只匹配阿拉伯数字日期，不支持中文日期；
- `chinese_to_int` 对 `万` 的组合处理不完整。

### 修复

1. 在 `_fact_patterns` 中为数量 2 增加 `两` 变体，并覆盖 `两万元`、`两年`、`两个` 等常见形式。
2. 扩展日期抽取/覆盖：
   - 支持 `二〇二五年九月一日`、`二〇二五年九月一日` 等中文日期；
   - canonical 仍为 `YYYY-MM-DD`；
   - 或者明确把中文日期作为“未抽取”记录在报告中，不能声称已支持。
3. 修复 `chinese_to_int` 的 `万/十万/百万` 组合；补充参数化测试。
4. 增加参数化回归：

```text
连续2年 / 连续两年
奖励2万元 / 奖励两万元
2025年9月1日 / 二〇二五年九月一日
10个工作日 / 十个工作日
```

### 退出条件

- 上述测试全部通过；
- 新旧 W3 20 题误拒不增加；如果新增拦截导致 d006 之外误拒，记录并复核；
- 不为了通过测试把 fact 抽取范围扩大到裸数字。

## 5. F4：trace 漏 scope issues

`qa/service.py` 正常路径写入的 trace：

```python
trace_extra["verification"] = {
    "issues": [issue.model_dump() for issue in verification.issues],
    ...
}
```

这里只包含 `verification.issues`，不包含 `scope.issues`。因此 `MIXED_VERSIONS`、`AUDIENCE_MISMATCH`、`VERSION_MISMATCH` 在 `QAResult.issues` 中存在，但在 trace 的 `verification` 中缺失。

### 修复

- 将 trace 的 `verification.issues` 改为 `merged_issues = [*scope.issues, *verification.issues]`；
- 或单独增加 `scope_issues` 字段；
- 增加测试：带 `MIXED_VERSIONS` / `AUDIENCE_MISMATCH` 的请求，trace 中必须出现对应 code。

## 7. F6：版本冲突口径

当前 W3 实现：

- 同一 `doc_id` 多个 active 版本，**只有 `effective_from` 相同**才 `VERSION_CONFLICT`；
- 生效日不同（培养方案 v2022/v2024 等届别版本）保留并记 `MIXED_VERSIONS` warning。

W3 设计原文写的是“多个重叠 active version → VERSION_CONFLICT”。当前实现更窄，但周记录已解释为 W3 v0 的届别版本处理。

### 处理

二选一，但必须一致：

- **保持当前实现**：更新 W3 设计/周记录为“W3 只处理生效日平局，完整重叠判断 W4”；不再声称实现设计原文的完整重叠规则；
- **实现完整重叠判断**：按版本文档的生效区间判断区间交叠；但会重新拒答 d013/d014，需先确认届别版本语义和 W4 版本解析。

推荐保持 v0，W4 接版本解析器时统一处理。

3. **未通过**：保持 W3 门禁未通过，W6 提示词/重写或 W4 前修复。

不能在没有人工标注的情况下写“W3 已通过”。
